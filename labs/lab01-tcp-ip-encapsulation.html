Initial Baseline State: Host PC-Client (10.1.1.10/24) and Web-Server (10.1.1.100/24) are directly connected in VLAN 1. Web-Server has an active HTTP daemon listening on TCP port 80.

📋 Engineering Requirements

Trace and analyze protocol encapsulation fields across the client-server interaction.

1. End-to-End Addressing & Service Verification:

  • Verify IP configuration on PC-Client (10.1.1.10/24) and Web-Server (10.1.1.100/24).
  • Confirm that the web service on Web-Server is actively listening on TCP port 80.

2. Layer 4 Transport Multiplexing & TCP 3-Way Handshake:

  • From PC-Client, initiate an HTTP GET request to http://10.1.1.100/.
  • Capture and analyze the 3 packets of the TCP connection establishment handshake:
    • Packet 1 (SYN): Client sends SYN=1, initial client sequence number (ISN), destination port 80, and a dynamic ephemeral source port (≥ 49152).
    • Packet 2 (SYN-ACK): Server responds with SYN=1, ACK=1, server ISN, and acknowledgment number = Client ISN + 1.
    • Packet 3 (ACK): Client completes handshake with ACK=1 and acknowledgment number = Server ISN + 1.

3. Layer 3 IPv4 Header Analysis:

  • Inspect the IPv4 packet header of the HTTP data packet:
    • Confirm Version is 4 and Internet Header Length (IHL) is 5 (20 bytes).
    • Verify Protocol ID is 6 (indicating TCP payload) rather than 17 (UDP) or 1 (ICMP).
    • Verify that the Time-to-Live (TTL) starts at 64 on the originating Linux host.

4. Layer 2 Ethernet II Frame Encapsulation & FCS:

  • Inspect the Ethernet frame carrying the packet:
    • Verify Destination MAC matches Web-Server MAC (5000.0002.0002).
    • Verify Source MAC matches PC-Client MAC (5000.0001.0001).
    • Verify Type field is 0x0800 (IPv4) rather than 0x0806 (ARP).
    • Confirm the presence of the 4-byte Frame Check Sequence (FCS) trailer calculated via CRC-32.

🔬 Architectural Breakdown & Design Logic

This lab deconstructs the core theoretical foundation of the entire CCNA exam: data encapsulation and protocol communication, as presented in Cisco Press Volume 1, Chapters 1 & 2.

1. Same-Layer vs. Adjacent-Layer Interaction

Cisco Press highlights two fundamental rules of networking communication:

  • Adjacent-Layer Interaction (On the Same Host): How a higher layer requests services from the layer directly below it (e.g., HTTP on PC-Client requests reliable transport from TCP; TCP hands segments down to IP).
  • Same-Layer Interaction (Across the Network): How the protocol on one device communicates with the corresponding protocol on the destination device using header information (e.g., TCP on PC-Client talks to TCP on Web-Server using Sequence and Acknowledgment numbers in the TCP header).

2. Port Number Ranges & Port Multiplexing

Layer 4 ports enable a host to run multiple network applications simultaneously over a single IP address:

  • Well-Known Ports (0 – 1023): Reserved for server-side daemons (e.g. 22 SSH, 23 Telnet, 53 DNS, 80 HTTP, 443 HTTPS).
  • Registered Ports (1024 – 49151): Vendor-specific application services.
  • Dynamic / Private / Ephemeral Ports (49152 – 65535): Randomly assigned by the client OS to track individual outgoing client connections.

3. The Role of the EtherType Field

The 2-byte Type field in the Ethernet II frame header identifies which Layer 3 protocol is encapsulated in the data payload:

  • 0x0800 = IPv4 Packet
  • 0x0806 = ARP (Address Resolution Protocol)
  • 0x86DD = IPv6 Packet
  • 0x8100 = 802.1Q VLAN Tagged Frame
