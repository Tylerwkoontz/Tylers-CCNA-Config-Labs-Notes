Lab 03: End-to-End Packet Delivery & ARP Resolution

Curriculum Focus: Cisco Press Official Cert Guide Vol 1, Part I (Chapter 3) • Topics: Host Subnet Logic, Default Gateway Forwarding, Address Resolution Protocol (ARP), and Layer 2 Frame Header De-encapsulation & MAC Rewrite.

🗺️ Topology, Addressing & Initial State

Scenario: You are deploying a routed boundary between two branch subnets (Subnet A: 10.1.1.0/24 and Subnet B: 10.1.2.0/24) connected via Router R1. You must configure gateway addressing, examine how hosts evaluate local vs. remote destinations, observe the ARP resolution process, and trace how Layer 2 MAC addresses change hop-by-hop while Layer 3 IP headers remain constant.

Initial Baseline State: Router R1 is running factory default configuration with all interfaces administratively shutdown. PC1 and PC2 have their IP addresses configured but empty ARP cache tables.

📋 Engineering Requirements

Configure the router and trace the end-to-end packet forwarding and ARP resolution logic.

1. Device Identification & Interface Addressing:

  • Configure the device hostname to R1.
  • Configure line con 0 with logging synchronous and exec-timeout 0 0.
  • Configure interface GigabitEthernet0/1 with IPv4 address 10.1.1.1 255.255.255.0 and a descriptive description. Enable the interface and bring the interface up.
  • Configure interface GigabitEthernet0/2 with IPv4 address 10.1.2.1 255.255.255.0 and a descriptive description. Enable the interface and bring the interface up.

2. Host Endpoint Provisioning:

  • Configure PC1 with IPv4 address 10.1.1.10, subnet mask 255.255.255.0, and default gateway 10.1.1.1.
  • Configure PC2 with IPv4 address 10.1.2.20, subnet mask 255.255.255.0, and default gateway 10.1.2.1.

3. Host Routing Evaluation & ARP Resolution:

  • Analyze the host routing logic when PC1 prepares to send an ICMP packet to PC2 (10.1.2.20): explain why PC1 targets the default gateway instead of sending directly to PC2.
  • From PC1, initiate an ICMP ping to 10.1.2.20.
  • Inspect PC1's ARP cache table (arp -n) and verify that PC1 resolves only the MAC address of its default gateway (R1 Gi0/1), not PC2's MAC address.

4. Router Layer 2 Header De-encapsulation & MAC Rewrite:

  • Inspect the ARP table on R1 using show ip arp to confirm that R1 holds ARP entries for both PC1 (10.1.1.10) on Gi0/1 and PC2 (10.1.2.20) on Gi0/2.
  • Verify how R1 strips the incoming Ethernet header from PC1, decrements the IP TTL by 1, and encapsulates the packet into a new Ethernet frame destined for PC2's MAC address before forwarding out Gi0/2.

5. Configuration Persistence:

  • Save the active running configuration to NVRAM on router R1.

🔬 Architectural Breakdown & Design Logic

This lab covers the single most fundamental packet-delivery process in computer networking, as explained in Cisco Press Volume 1, Chapter 3.

1. Host Routing Logic: Local vs. Remote Subnet

Before an endpoint sends an IPv4 packet, its TCP/IP stack performs a bitwise comparison:

  • Rule: Compare the destination IPv4 address against the host's own IPv4 address using the configured subnet mask.
  • Local Destination: If the destination is in the same subnet (e.g. 10.1.1.15), the host sends an ARP request directly for the destination host's MAC.
  • Remote Destination: If the destination is in a different subnet (e.g. 10.1.2.20), the host never attempts to ARP for the remote host. Instead, it looks up the MAC address of its configured Default Gateway (10.1.1.1) and forwards the frame to the router!

2. ARP Broadcast vs. Unicast Reply Mechanics

When PC1 does not have the gateway MAC in its ARP table:

  • ARP Request: Sent as a Layer 2 broadcast (FF:FF:FF:FF:FF:FF) asking: "Who has 10.1.1.1? Tell 10.1.1.10". All devices in VLAN/Subnet A process the broadcast.
  • ARP Reply: Router R1 recognizes its own IP, records PC1's MAC in its ARP table, and replies with a Layer 2 unicast frame containing its physical MAC address (0000.5E00.0101).

3. The Layer 2 Frame Rewrite Process

When Router R1 receives the frame on Gi0/1:

  1. It verifies the Frame Check Sequence (FCS) to confirm no bit errors occurred.
  2. It strips (de-encapsulates) the Layer 2 Ethernet header and trailer.
  3. It decrements the IP header Time-to-Live (TTL) field by 1 (if TTL reaches 0, the packet is discarded and an ICMP Time Exceeded is returned).
  4. It recalculates the IPv4 header checksum.
  5. It consults its routing table for destination 10.1.2.20, identifying outgoing interface Gi0/2.
  6. It encapsulates the IP packet in a brand new Layer 2 Ethernet header with Source MAC = R1 Gi0/2 and Destination MAC = PC2 before transmitting.
