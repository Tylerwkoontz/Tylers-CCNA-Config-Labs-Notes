📋 Engineering Requirements

Configure the topology devices to meet the following engineering specifications. Reference the addressing table and topology map to determine correct IP parameters and routing next-hops.

1. Device Hostnames & Console Usability:

  • Configure the device hostname R1 on Router 1 and R2 on Router 2.
  • On both routers, configure console line 0 so unsolicited syslog messages do not interrupt command entry.
  • Disable console inactivity session timeouts on both routers.

2. Router Interfaces & Enablement:

  • On R1, configure IPv4 addresses, dotted-decimal subnet masks, and descriptions on GigabitEthernet0/0 (WAN Link) and GigabitEthernet0/1 (Sales LAN) according to the addressing table.
  • On R2, configure IPv4 addresses, dotted-decimal subnet masks, and descriptions on GigabitEthernet0/0 (WAN Link) and GigabitEthernet0/1 (Engineering LAN) according to the addressing table.
  • Ensure all configured router interfaces are enabled and operational (no shutdown).

3. IPv4 Static Routing:

  • On R1, configure an IPv4 static route to reach the Engineering Department LAN subnet (192.168.100.64/27) using R2's point-to-point WAN interface IP address as the next-hop.
  • On R2, configure an IPv4 static route to reach the Sales Department LAN subnet (192.168.100.0/26) using R1's point-to-point WAN interface IP address as the next-hop.

4. Host Endpoints & Configuration Persistence:

  • Configure PC-Sales and PC-Eng with their respective IPv4 addresses, prefix lengths, and default gateways per the addressing specification.
  • Save the running configuration to NVRAM on both routers so changes persist across reboots.

🔬 Architectural Breakdown & Design Logic

This lab reinforces core Volume 1 Chapter 9 skills: converting prefix lengths to dotted-decimal notation in Cisco IOS, assigning interface addresses, building static routing tables, and tracing end-to-end packet paths. Here is the engineering logic behind each requirement group:

1. Dotted-Decimal Masks in Cisco IOS vs. CIDR

While modern documentation and network planners use CIDR prefixes like /26, /27, and /30, Cisco IOS interface and static route configuration commands require dotted-decimal subnet masks:

  • /26 (Sales LAN): 26 mask bits → 255.255.255.192 (64 total IPs, 62 usable hosts).
  • /27 (Engineering LAN): 27 mask bits → 255.255.255.224 (32 total IPs, 30 usable hosts).
  • /30 (WAN Interconnect): 30 mask bits → 255.255.255.252 (4 total IPs, 2 usable host IPs).

Entering ip address 192.168.100.1/26 directly on a Cisco IOS interface will trigger an invalid input syntax error—you must always convert to dotted decimal.

2. Static Routing: Next-Hop IP vs. Outgoing Interface

In Cisco IOS, an IPv4 static route is defined using ip route <dest-subnet> <dest-mask> <next-hop-ip | exit-interface>.

On point-to-point serial links, specifying either the outgoing interface or next-hop IP produces the same result. However, on Ethernet links (such as GigabitEthernet0/0 in this lab), specifying only the exit interface forces the router to broadcast an ARP request for every single destination host address it routes, exhausting router ARP cache memory and causing performance degradation (Proxy ARP dependency). Best practice is to always specify the next-hop IPv4 address (192.168.100.98 on R1, and 192.168.100.97 on R2).

3. The "Return Routing" Trap (Asymmetric Failure)

A very common exam and real-world trap occurs when an engineer configures the forward static route on R1 (allowing PC-Sales to send packets to PC-Eng), but forgets the return route on R2.

When PC-Sales pings PC-Eng, the ICMP Echo Request arrives successfully at PC-Eng. But when PC-Eng generates an ICMP Echo Reply destined for 192.168.100.10, Router 2 consults its routing table, finds no route matching 192.168.100.0/26, and immediately drops the packet! Always verify both forward and return path routing tables.

4. Connected (C) vs. Local (L) Routing Table Entries

When viewing show ip route on Cisco IOS 15+, notice two distinct route types for each enabled interface:

  • C (Connected): Represents the entire subnet attached to the interface (e.g., 192.168.100.0/26). Used for forwarding traffic to other hosts in that subnet.
  • L (Local): Represents the router's own specific interface IP with a /32 host mask (e.g., 192.168.100.1/32). Used by the router's internal CPU to quickly determine whether an incoming packet is destined for the router itself.
