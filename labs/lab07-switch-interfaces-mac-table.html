📋 Engineering Requirements

Configure both switches to meet the following interface optimization and Layer 2 forwarding requirements.

1. Device Identification & Interface Documentation:

  • Configure the hostname SW1 on Switch 1 and SW2 on Switch 2.
  • On both switches, configure line con 0 with logging synchronous and exec-timeout 0 0.
  • Add meaningful interface descriptions on GigabitEthernet0/1 identifying the neighbor switch and port ID.
  • Add interface descriptions on GigabitEthernet0/2 identifying the connected host endpoint.

2. Inter-Switch Link Optimization (Speed & Duplex):

  • On the inter-switch link (GigabitEthernet0/1 on both SW1 and SW2), explicitly disable autonegotiation and statically set the port speed to 1000 Mbps.
  • Statically lock the duplex mode on GigabitEthernet0/1 to full duplex on both switches.
  • Ensure the host-facing ports (GigabitEthernet0/2) remain configured for dynamic speed and duplex autonegotiation.

3. Dynamic MAC Address Learning & Verification:

  • Initiate an ICMP ping from PC-A to PC-B to populate the dynamic MAC address tables across both switches.
  • Verify on SW1 that PC-A's source MAC address is learned dynamically on port Gi0/2, and PC-B's MAC address is learned on port Gi0/1.
  • Verify on SW2 that PC-B's MAC address is learned on port Gi0/2, and PC-A's MAC address is learned on port Gi0/1.

4. Static MAC Address Security:

  • On SW1, configure a permanent static MAC address entry mapping printer MAC 0050.7966.6800 to interface GigabitEthernet0/3 in VLAN 1.
  • Verify that the static MAC entry appears as permanent and does not age out.

5. Configuration Persistence:

  • Save the active running configuration to startup NVRAM on both switches.

🔬 Architectural Breakdown & Design Logic

This lab covers core Volume 1 Chapter 5 & 7 concepts: Ethernet frame switching logic, MAC address learning, and interface physical layer troubleshooting.

1. The 3 Core Actions of an Ethernet Switch

Every Layer 2 switch executes three fundamental algorithms upon receiving an Ethernet frame:

  • Step 1: Learn (Source MAC): The switch inspects the Source MAC address in the frame header. If the MAC is not in the table (or is listed on a different port), the switch adds or updates the entry with the ingress port and resets the 300-second aging timer.
  • Step 2: Forward vs. Filter vs. Flood (Destination MAC):
    • Known Unicast: Destination MAC is in the table on a different port → Forward out only that specific port.
    • Filtered (Discarded): Destination MAC is in the table on the same port the frame arrived on → Drop frame (no transmission needed).
    • Unknown Unicast / Broadcast / Multicast: Destination MAC is not in the table (or is all-Fs) → Flood out all active ports in the VLAN except the ingress port.

2. The Autonegotiation "Parallel Detection" Trap & Duplex Mismatches

When one side of a 10/100 Mbps link is statically configured (e.g. speed 100, duplex full) and the other side is left on auto, IEEE autonegotiation fails because the static side sends no Fast Link Pulses (FLPs).

The autonegotiating side uses parallel detection: it can detect the physical electrical speed (100 Mbps), but defaults to half duplex! This creates a catastrophic duplex mismatch:

  • The full-duplex side transmits anytime and ignores collisions.
  • The half-duplex side detects collisions while receiving, aborts transmission, and increments late collisions and CRC errors.
  • Rule: Either enable autonegotiation on both ends, or hardcode speed AND duplex on both ends!

3. Decoding "a-full" vs "full" in show interfaces status

In Cisco IOS show interfaces status:

  • a-full / a-1000: The prefix a- means the switch autonegotiated that setting with its link partner.
  • full / 1000: No prefix means the parameter was manually hardcoded by the network administrator.

4. Common Layer 1/2 Interface Error Counters

When troubleshooting interfaces using show interfaces <type/num>:

  • Runts: Frames smaller than the minimum 64-byte Ethernet frame size (often caused by collisions).
  • Giants: Frames exceeding maximum IEEE 1518-byte MTU size without baby-giant/jumbo configuration.
  • CRC (Cyclic Redundancy Check): Frame Check Sequence (FCS) failed math check (caused by electrical noise, faulty cable, or duplex mismatch).
  • Late Collisions: Collisions occurring after the first 64 bytes (512 bits) of transmission—almost always diagnostic of a duplex mismatch.
