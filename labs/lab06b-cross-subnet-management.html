Lab 06B: Cross-Subnet Remote Switch Management

Curriculum Focus: Cisco Press Official Cert Guide Vol 1, Part II (Chapter 6) • Topics: The Crucial Role of `ip default-gateway` on Layer 2 Switches, Cross-Subnet SVI Reachability, and VTY SSH Hardening.

🗺️ Topology, Addressing & Initial State

Scenario: You are managing a remote campus switch (SW1 with SVI in Subnet 192.168.1.0/24) from a central Network Operations Center workstation (Admin-NOC in Subnet 10.1.1.0/24) through a default gateway router (R1). You must diagnose why remote SSH fails when ip default-gateway is missing on a Layer 2 switch, and configure full remote management.

Device Interface IPv4 Address Subnet Mask Default Gateway Role
Admin-NOC eth0 10.1.1.50 255.255.255.0 10.1.1.1 Remote Management Workstation
R1 GigabitEthernet0/1 10.1.1.1 255.255.255.0 N/A NOC Subnet Gateway
R1 GigabitEthernet0/2 192.168.1.1 255.255.255.0 N/A Campus Switch Subnet Gateway
SW1 Vlan 1 (SVI) 192.168.1.2 255.255.255.0 192.168.1.1 Remote Access SVI Management
Initial Baseline State: Router R1 is fully configured and operational with both subnets connected. Switch SW1 has interface vlan 1 configured with IP 192.168.1.2/24 and SSH enabled, but NO default gateway is configured. Admin-NOC cannot reach SW1.

📋 Engineering Requirements

Diagnose the cross-subnet connectivity failure, configure the default gateway, and harden the switch control plane.

1. Diagnose Cross-Subnet Management Failure:

  • From Admin-NOC (10.1.1.50), verify ping reachability to Router gateway 10.1.1.1 and 192.168.1.1.
  • Attempt to ping Switch SW1 SVI (192.168.1.2) from Admin-NOC and observe 100% packet loss.
  • Explain why SW1 can receive incoming ICMP/SSH packets from Admin-NOC, but fails to reply without an ip default-gateway command.

2. Configure Layer 2 Default Gateway on SW1:

  • On SW1, configure the global default gateway to point to Router R1's local interface IP: 192.168.1.1.
  • Re-test the ICMP ping from Admin-NOC to 192.168.1.2 and confirm 100% success.

3. Hardened Remote SSH Management:

  • Configure IP domain name certskills.internal on SW1.
  • Create local administrative username admin with secret password AdminSSH#2026.
  • Generate 2048-bit RSA keys and enable SSH version 2.
  • On VTY lines 0 through 15, enforce login local and restrict transport to transport input ssh only.
  • Set inactivity session timeout on VTY lines to 10 minutes (exec-timeout 10 0).

4. Configuration Persistence:

  • Save the active running configuration to startup NVRAM on SW1 and R1.

🔍 Verification & Validation Steps

Run these verification commands to validate default gateway routing and remote SSH session establishment.

1. Verify Default Gateway on Switch

Execute show ip default-gateway or inspect the running-config on SW1:

SW1# show running-config | include default-gateway
ip default-gateway 192.168.1.1
2. Cross-Subnet SSH Session from NOC Admin

From Admin-NOC, initiate an SSH session across the router to the switch:

Admin-NOC:~$ ssh admin@192.168.1.2
Password: [AdminSSH#2026]

SW1> enable
Password: [cisco123]
SW1#

🔬 Architectural Breakdown & Design Logic

This lab reinforces the critical Layer 2 switch management rule explained in Cisco Press Volume 1, Chapter 6.

1. Why Layer 2 Switches Require `ip default-gateway`

A Layer 2 Catalyst switch does not maintain a routing table for forwarding user transit traffic. However, its own internal TCP/IP management stack behaves exactly like a host endpoint:

  • When Admin-NOC (10.1.1.50) sends an SSH packet to SW1 (192.168.1.2), Router R1 forwards the packet to SW1. SW1 receives the frame successfully.
  • However, when SW1 prepares its TCP ACK reply destined for 10.1.1.50, SW1 compares 10.1.1.50 against its local SVI mask (192.168.1.0/24) and realizes the destination is in a remote subnet.
  • Without the ip default-gateway 192.168.1.1 command, SW1 has no route and drops the return packet immediately!
