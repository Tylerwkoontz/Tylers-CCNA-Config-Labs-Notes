Lab 07B: Layer 1/2 Switch Interface Diagnostics & Duplex Mismatch Isolation

Curriculum Focus: Cisco Press Official Cert Guide Vol 1, Part II (Chapters 5 & 7) • Topics: Troubleshooting Interface Operational States, Autonegotiation Failure Diagnostics, Decoding `show interfaces` Error Counters (Late Collisions, CRC, Runts), and Remediation.

🗺️ Topology, Addressing & Initial State

Scenario: Users on PC-A report severe intermittent packet loss and sluggish throughput when accessing Server-B. You are tasked with analyzing the physical and data-link layers on switches SW1 and SW2, isolating the root cause of late collisions and frame corruption, and restoring clean gigabit communication.

Initial Baseline State: The inter-switch link between SW1 and SW2 has a misconfiguration: SW1 has speed 100 and duplex full hardcoded on Gi0/1, while SW2 is configured with speed auto and duplex auto. A light ping passes, but bulk file transfers experience heavy CRC errors and packet drops.

📋 Engineering Requirements

Isolate the physical/data-link fault, analyze interface error counters, and standardize interface configuration.

1. Diagnose Operational State & Duplex Settings:

  • Execute show interfaces status on SW1 and SW2 to compare the duplex and speed columns for port Gi0/1.
  • Identify that SW1 displays full (hardcoded), while SW2 displays a-half (autonegotiated to half duplex via parallel detection).

2. Analyze Interface Error Counters:

  • Generate 100 large ICMP ping packets from PC-A to Server-B (ping -c 100 -s 1400 10.1.1.100).
  • Execute show interfaces gigabitEthernet 0/1 on both switches.
  • Observe and record the counter increments:
    • On SW2 (Half-Duplex Side): Note the rise in late collisions (collisions occurring after the 64-byte slot time).
    • On SW1 (Full-Duplex Side): Note the rise in CRC errors and input errors (corrupted frames aborted by the half-duplex side).

3. Remediate & Standardize Speed/Duplex Configuration:

  • Remediate the inter-switch link by standardizing GigabitEthernet0/1 on both SW1 and SW2 to speed 1000 and duplex full (or dynamic autonegotiation on both ends).
  • Clear interface counters using clear counters gigabitEthernet 0/1 on both switches.
  • Re-run the large packet ping test and verify 0 late collisions, 0 CRC errors, and 0 packet drops.

4. Configuration Persistence:

  • Save the active running configuration to startup NVRAM on both switches.

🔬 Diagnostic Counter Interpretation

Counter Name Definition Primary Root Cause
Late Collisions Collisions occurring after the first 64 bytes (512 bits) of transmission. Duplex Mismatch (One side is Full Duplex and transmits while the other side is in Half Duplex). Also cable length > 100m.
CRC Errors Frame Check Sequence (FCS) calculation did not match incoming frame bits. Electrical EMI noise, damaged physical copper cable, faulty transceiver, or collision-induced frame corruption.
Runts Frames received that are smaller than the minimum IEEE 64-byte size. Collisions aborting transmission early, or faulty network interface card.
Giants Frames received that exceed the standard 1518-byte MTU size. Host sending baby-giant/jumbo frames (e.g. 9000 bytes) without switch jumbo MTU configuration.

🔬 Architectural Breakdown & Design Logic

This lab covers the single most common real-world Ethernet troubleshooting scenario on the CCNA exam, as detailed in Cisco Press Volume 1, Chapter 7.

1. Why Duplex Mismatches Still Pass `ping` Tests

A deceptive characteristic of a duplex mismatch is that single, small ICMP echo request packets (64 bytes) often succeed with 0% loss!

Because traffic is light, the chances of both ends transmitting at the exact same millisecond are low. However, as soon as a user transfers a file (FTP, HTTP, backup) and packets flow bidirectionally simultaneously:

  • The full-duplex side transmits continuously without checking for line availability.
  • The half-duplex side senses the incoming electrical carrier while attempting to transmit its own frame, senses a collision, aborts, and logs a late collision!
