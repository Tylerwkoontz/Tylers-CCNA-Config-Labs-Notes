Lab 06: Basic Switch Management, SVI & Hardened SSH Access

Curriculum Focus: Cisco Press Official Cert Guide Vol 1, Part II (Chapters 4 & 6) • Topics: CLI Navigation, SVI (VLAN 1 IP), Default Gateway, Console Line Hardening, and Secure SSH v2 Configuration.

🗺️ Topology, Addressing & Initial State

Scenario: You are installing a new Cisco Catalyst switch into the campus access layer. You must establish base management settings, configure a Switch Virtual Interface (SVI) on VLAN 1 for in-band management, and configure encrypted SSH v2 remote management while disabling insecure Telnet access.

Device Interface IPv4 Address Subnet Mask Default Gateway Management Purpose
SW1 Vlan 1 (SVI) 192.168.1.2 255.255.255.0 192.168.1.1 In-Band Switch Management
SW1 GigabitEthernet0/1 Unassigned N/A N/A Access Port to PC-Admin (VLAN 1)
PC-Admin eth0 192.168.1.10 255.255.255.0 192.168.1.1 Network Engineer Management Host
Initial Baseline State: Switch SW1 is running factory default configuration with default hostname Switch. No management IP or login security is enabled. PC-Admin has IP 192.168.1.10/24 pre-configured on eth0.

📋 Engineering Requirements

Configure the switch to meet the following production management and security specifications.

1. Device Hostname & Security Banner:

  • Configure the device hostname to SW1.
  • Configure a Message-of-the-Day (MOTD) login banner containing a clear authorized-access warning warning that unauthorized access is strictly prohibited.

2. Console Line & Privileged Mode Hardening:

  • Secure privileged EXEC mode with the strong secret password cisco123.
  • Configure the console port (line con 0) with password conpass and require password authentication upon login.
  • Configure console line 0 so unsolicited syslog messages do not interrupt command typing, and disable console inactivity session timeouts.
  • Enable Cisco IOS password encryption service so plain-text passwords in the running-config are obfuscated.

3. Switch Management Interface (SVI) & Gateway:

  • Configure the Switch Virtual Interface (SVI) for VLAN 1 with IPv4 address 192.168.1.2 and subnet mask 255.255.255.0.
  • Enable the SVI interface administratively and bring the interface up.
  • Configure the switch default gateway to 192.168.1.1.

4. Hardened Secure Shell (SSH v2) Remote Management:

  • Set the IP domain name to certskills.internal.
  • Generate an RSA crypto key pair with a modulus size of 2048 bits.
  • Enforce SSH Version 2 globally.
  • Create a local administrative username admin with secret password AdminSSH#2026.
  • Configure VTY lines 0 through 15 to require local username/password authentication.
  • Restrict VTY inbound transport to SSH only, preventing unencrypted Telnet connections.

5. Configuration Persistence:

  • Save the active running configuration to NVRAM startup configuration.

🔬 Architectural Breakdown & Design Logic

This lab reinforces foundational Volume 1 Chapter 4 & 6 skills: securing the Cisco switch control plane, managing SVIs, and enforcing cryptographic remote administration.

1. Why Does the SVI Require an Active Access/Trunk Port?

On a Cisco Catalyst Layer 2 switch, configuring ip address on interface vlan 1 and entering no shutdown is not enough for the interface to reach the up / up state!

An SVI is a logical Layer 3 interface. For an SVI to reach the operational up/up state, at least one physical Ethernet port assigned to that VLAN (or a trunk allowing that VLAN) must be in the active, forwarding up/up state. If all physical ports in VLAN 1 are unplugged or down, the SVI automatically transitions to down/down.

2. Prerequisites for Cisco IOS SSH Key Generation

When running crypto key generate rsa, Cisco IOS uses the router/switch hostname and IP domain-name to name the encryption key (e.g., SW1.certskills.internal).

  • If you attempt to generate RSA keys before setting a hostname or domain name, IOS will reject the command.
  • Specifying a modulus of 1024 bits or greater (2048 is recommended) is required to enable SSH Version 2. A 512-bit key restricts the switch to insecure SSH Version 1.

3. VTY Transport Input & Login Local Traps

On VTY lines, failing to specify transport input ssh leaves Telnet enabled by default, allowing network attackers to sniff cleartext administrator passwords in transit.

Furthermore, configuring login local instructs the switch to check the local database for usernames created with the username <user> secret <pass> global command. If you configure login local without first creating a local user, you will lock yourself out of VTY management upon disconnecting!

4. Cisco Type 7 Password Encryption Limitations

The service password-encryption command applies Cisco proprietary Type 7 encryption to simple passwords (like console line passwords).

Type 7 is not true cryptography—it is a simple Vigenère cipher that can be decrypted online in seconds. It only protects against "over-the-shoulder" viewing of the screen. For actual security, always use enable secret and username ... secret, which utilize irreversible MD5, SHA-256 (Type 8), or Scrypt (Type 9) hashing.
