📋 Engineering Requirements

Practice the following Cisco IOS CLI navigation, command recall, and memory management procedures.

1. Initial Setup Bypass & EXEC Mode Hierarchy:

  • Bypass the Initial Configuration Dialog by typing no to enter User EXEC mode (Switch>).
  • Enter Privileged EXEC mode (Switch#) using the enable command.
  • Enter Global Configuration mode (Switch(config)#) using configure terminal.
  • Navigate into interface configuration submode for GigabitEthernet0/1 (Switch(config-if)#), and line configuration submode for line con 0 (Switch(config-line)#).
  • Practice returning to Privileged EXEC mode directly from submodes using the end command or Ctrl+Z shortcut.

2. Context-Sensitive Help & CLI Editing Shortcuts:

  • Use context-sensitive help (?) to list all commands starting with the letter s (s?), and all parameters valid after show (show ?).
  • Practice command auto-completion using the <Tab> key (e.g. type conf t and press Tab → configure terminal).
  • Practice cursor navigation shortcuts: Ctrl+A (jump to beginning of line), Ctrl+E (jump to end of line), and Ctrl+U (erase entire line).

3. Command History Buffer Sizing & Recall:

  • Resize the active terminal session history buffer to store 50 commands to retain up to 50 commands in the recall buffer.
  • Recall previous commands using the Up Arrow (or Ctrl+P) and next commands using the Down Arrow (or Ctrl+N).
  • Display the list of currently buffered commands in memory using show history.

4. Executing Privileged Commands from Submodes (`do` Prefix):

  • Enter interface configuration mode for GigabitEthernet0/1.
  • Without exiting configuration mode, execute show ip interface brief and show running-config using the do prefix (e.g. do show ip interface brief).

5. Cisco Memory Subsystems & Configuration Persistence:

  • Set the switch hostname to SW1.
  • Compare the active configuration in volatile RAM (show running-config) with the saved configuration in non-volatile NVRAM (show startup-config).
  • Save the active running configuration to startup NVRAM using copy running-config startup-config (and observe the [startup-config]? destination confirmation).
  • View the contents of Flash memory using show flash: to observe the Cisco IOS XE image binary file.

🔬 Architectural Breakdown & Design Logic

This lab reinforces foundational Volume 1 Chapter 4 mechanics: navigating Cisco IOS hierarchy, leveraging editing shortcuts, and managing Cisco device memory subsystems.

1. The 4 Cisco Device Memory Subsystems

Every Cisco router and switch utilizes four distinct physical memory types:

  • RAM (Random Access Memory): Fast, volatile memory. Holds the active running-config, routing table, ARP cache, MAC address table, and running IOS software code. Lost upon reboot or power loss!
  • NVRAM (Non-Volatile RAM): Permanent storage for the startup-config and configuration register. Retains its contents across reboots.
  • Flash Memory: Permanent electrically erasable PROM (EEPROM). Stores Cisco IOS / IOS-XE binary operating system image files.
  • ROM (Read-Only Memory): Permanent chip containing bootstrap startup code, Power-On Self-Test (POST), and ROMMON mini-recovery OS.

2. `copy running-config startup-config` vs `write memory`

While older Cisco network engineers frequently use the shorthand write memory (or wr), the official Cisco certification exam and modern documentation emphasize copy running-config startup-config.

The copy command follows the universal syntax copy <source-url> <destination-url>, allowing engineers to backup configurations to TFTP servers, Flash cards, or FTP servers (e.g. copy running-config tftp:).

3. The `do` Command: Power and Context

Normally, EXEC commands (like show, ping, debug) can only be entered at the Privileged EXEC prompt (#). Entering show ip int brief while inside (config-if)# results in an IOS syntax error.

By prefixing the command with do (e.g. do show ip interface brief), IOS executes the Privileged EXEC command without forcing you to exit your configuration submode. Note: Context-sensitive help (?) after do is limited on older IOS versions.
